# Q-Junior Management System (Backend & Frontend Summary)

ระบบจัดการฐานข้อมูลครูและ Ticket (ใบงาน) สำหรับโครงการ Q-Junior โดยใช้ Rust (Axum) เป็น Backend และ HTML/JavaScript เป็น Frontend

## 🛠 โครงสร้างระบบ (System Architecture)

### 1. ฐานข้อมูล (SQLite)
ระบบใช้ SQLite (`files.db`) ในการจัดเก็บข้อมูล แบ่งออกเป็น 5 ตารางหลัก:
- **files**: เก็บดัชนีรายชื่อไฟล์และโฟลเดอร์จากเครื่องเพื่อใช้ในการค้นหา
- **tickets**: ข้อมูลหลักของใบงาน (เลขที่, ผู้ประสานงานโครงการ, วันที่, สถานะ)
- **ticket_schools**: ความสัมพันธ์ระหว่าง Ticket กับโรงเรียน (ผู้ประสานงานโรงเรียน, ค่าใช้จ่าย)
- **ticket_teachers**: รายชื่อครูที่ผูกกับ Ticket นั้นๆ (ใช้สำหรับเก็บประวัติ)
- **teachers**: ทำเนียบรายชื่อครูทั้งหมด (Master Data) ที่จะถูก Sync เมื่อ Ticket สถานะเป็น 'Done'

### 2. Backend (Rust + Axum)
- **Framework**: Axum (Web Framework), Rusqlite (Database), Tokio (Runtime)
- **Features**:
    - Multi-threading: ใช้ `spawn_blocking` เพื่อให้ SQL ไม่ขัดขวางการทำงานของ Web Server
    - Transaction: ใช้ SQL Transaction ในการบันทึก Ticket เพื่อให้ข้อมูลในทุกตารางถูกต้องแม่นยำ
    - Incremental Indexing: ระบบสแกนไฟล์แบบตรวจสอบเฉพาะส่วนที่เปลี่ยนแปลง

## 🩹 การแก้ไขล่าสุด (Recent Fixes & Updates)

### 1. การแยกผู้ประสานงาน (Coordinator Separation)
- **ปัญหา**: เดิมระบบมีผู้ประสานงานที่เดียว ทำให้สับสนระหว่างคนคุมโครงการกับคนหน้างานที่โรงเรียน
- **การแก้ไข**: 
    - เพิ่มคอลัมน์ `coordinator` ในตาราง `ticket_schools` เพื่อเก็บชื่อผู้ประสานงานของแต่ละโรงเรียนแยกกัน
    - คงคอลัมน์ `coordinator` ในตาราง `tickets` ไว้สำหรับผู้ประสานงานโครงการหลัก

### 2. แก้ไข Bug 'no such column: coordinator'
- **ปัญหา**: ระบบ Panic (พัง) ขณะพยายามดึงค่า `coordinator` จากตาราง `ticket_teachers` ซึ่งไม่มีคอลัมน์นี้
- **การแก้ไข**: ปรับปรุง SQL ในฟังก์ชัน `ticket_done` และ `update_ticket` ให้เรียกเฉพาะคอลัมน์ที่มีอยู่จริง (`school`, `name`, `level`, `course`)

### 3. การรันเลข Ticket ID (SMB-Q)
- **ปัญหา**: เลข Ticket ไม่รันต่อ หรือไม่ปรากฏ
- **การแก้ไข**: เปลี่ยน Logic จากการใช้ `COUNT(*)` เป็นการใช้ `MAX(id) + 1` เพื่อป้องกันเลขซ้ำกรณีมีการลบ Ticket เก่าออก

### 4. การแสดงผลหน้าโรงเรียน (School Tickets View)
- **ปัญหา**: Ticket หายไปจากหน้าโรงเรียนหากยังกรอกข้อมูลไม่ครบ
- **การแก้ไข**: เปลี่ยนจาก `JOIN` เป็น `LEFT JOIN` ในฟังก์ชัน `get_school_tickets` เพื่อให้ Ticket แสดงผลเสมอแม้ข้อมูลผู้ประสานงานโรงเรียนจะยังเป็นค่าว่าง

## 🚀 วิธีการใช้งาน (Usage)
1. **เพิ่ม Ticket**: กรอกรายละเอียดหลัก เลือกโรงเรียน และใส่รายชื่อครู
2. **หน้าโรงเรียน**: ตรวจสอบ Ticket ที่เกี่ยวข้องกับโรงเรียนนั้นๆ และจัดการค่าใช้จ่าย/ผู้ประสานงานโรงเรียน
3. **การปิดงาน (Done)**: เมื่อกดสถานะ Done ระบบจะทำการคัดลอกรายชื่อครูจาก Ticket ไปยังฐานข้อมูลหลัก (`teachers`) โดยอัตโนมัติ
